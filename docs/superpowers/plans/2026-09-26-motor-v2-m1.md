**Objetivo:** construir o pacote `siftool` (motor novo), com API `inspect`/`clean`/`verify`, formatos JPEG, PNG e WEBP, três modos e CLI. O selo falha fechado e os testes provam que a limpeza não altera os pixels.

**Arquitetura:** cada formato é um handler que desmonta o arquivo em blocos (`ESSENTIAL`, `METADATA` ou `UNKNOWN`). Um planner decide, para cada bloco, entre manter, remover ou reescrever, conforme o modo. O handler monta a saída num temporário, e o `verify` relê essa saída com o mesmo leitor antes de ela receber o nome final. Leitores de EXIF, XMP, C2PA, ICC e IPTC só classificam o conteúdo; quem remove é o planner.

**Stack:** Python ≥ 3.11 (ambiente de desenvolvimento: 3.14.7). Em tempo de execução, só biblioteca padrão. pytest e Pillow só nos testes. setuptools com layout `src/`.

**Spec:** `docs/superpowers/specs/2026-09-26-motor-v2-design.md`. Leia junto com este plano. O M2 (BMFF, HEIC, MP4) terá plano próprio.

## Refinamentos em relação à spec

São decisões de implementação, sem efeito visível para o usuário:

1. **Dados após o fim do arquivo viram um bloco.** São modelados como `Block(kind=METADATA, tag="TRAILING")` com categoria `extras`. `Container.trailing` passa a ser uma propriedade derivada desse bloco. Assim o planner e o verify tratam trailing como qualquer outro metadado proibido.
2. **Imagens são lidas inteiras em `bytes`, não via `mmap`.** Com `mmap`, fatias `memoryview` ainda vivas impedem fechar o mapeamento no Windows (`BufferError`). O teto de 512 MB continua valendo, e o `mmap` fica para vídeo no M2. Por isso `parse`/`Container.source` recebem um buffer com `.find()` e fatiamento: `bytes` no M1, `mmap` no M2.
3. **`CleanResult.notes` é novo:** notas informativas do planner (como o aviso do modo Máximo). As notas de `Verdict.notes` são só as ressalvas da verificação, que levam a `WARNINGS`.
4. **`rewrite()` devolve o bloco completo** (marcador, tamanho e CRC incluídos). Os blocos reescrevíveis guardam seus bytes em `Block.raw`, por isso `rewrite(block, allowed)` não precisa do container.

```python
import os, pytest
from pathlib import Path
from siftool.safe_io import load, check_destination, AtomicOutput, TEMP_MARKER
from siftool.errors import CorruptFileError, UnsafeFileError, SameFileError, DestinationExistsError

def test_load_empty_file_is_corrupt(tmp_path):
    p = tmp_path / "e.jpg"; p.write_bytes(b"")
    with pytest.raises(CorruptFileError): load(p)

def test_load_over_limit_is_unsafe(tmp_path):
    p = tmp_path / "big.png"; p.write_bytes(b"x" * 11)
    with pytest.raises(UnsafeFileError): load(p, max_bytes=10)

def test_same_file_is_refused_even_with_different_spelling(tmp_path):
    p = tmp_path / "a.png"; p.write_bytes(b"1")
    other = Path(str(p).upper()) if os.name == "nt" else p
    with pytest.raises(SameFileError): check_destination(p, other, overwrite=True)

def test_existing_destination_needs_overwrite(tmp_path):
    s = tmp_path / "a.png"; d = tmp_path / "b.png"; s.write_bytes(b"1"); d.write_bytes(b"2")
    with pytest.raises(DestinationExistsError): check_destination(s, d, overwrite=False)
    check_destination(s, d, overwrite=True)

def test_atomic_output_commit_and_discard(tmp_path):
    d = tmp_path / "out.png"
    a = AtomicOutput(d)
    with a.open() as f: f.write(b"data")
    assert TEMP_MARKER in a.path.name and a.path.parent == tmp_path and not d.exists()
    a.commit(); a.discard()
    assert d.read_bytes() == b"data" and not list(tmp_path.glob(f"*{TEMP_MARKER}*"))
    b = AtomicOutput(tmp_path / "gone.png")
    with b.open() as f: f.write(b"x")
    b.discard()
    assert not list(tmp_path.glob(f"*{TEMP_MARKER}*")) and not (tmp_path / "gone.png").exists()
```

`detail` por tipo TIFF:
- ASCII → texto até o `\0`;
- RATIONAL/SRATIONAL → `"n/d"` (vários valores separados por `", "`);

Layout do escritor mínimo:
1. `b"MM\x00\x2a"` + offset do IFD0 = 8.
2. IFD0 com as entradas permitidas ordenadas por tag, mais `ExifIFDPointer` (0x8769, LONG) se houver tags do ExifIFD. Próximo IFD = 0.
3. Valores fora de linha do IFD0.
4. ExifIFD com `ExifVersion` (0x9000, UNDEFINED, 4, `b"0232"`) + as permitidas, e depois seus valores.

Offsets alinhados em par. Valores convertidos para big-endian por tipo:
- 1/2/6/7 → cópia;
- 3/8 → `H`/`h`;
- 4/9 → `I`/`i`;
- 5/10 → pares `II`/`ii`;
- 11 → `f`;
- 12 → `d`.

```
    if p < 0 or p + 1 >= len(data): raise CorruptFileError("truncated JPEG scan")
    n = data[p + 1]
```

```python
def mutate(data: bytes, rng: random.Random) -> bytes:
    d = bytearray(data); kind = rng.randrange(4)
    if kind == 0: return bytes(d[:rng.randrange(1, len(d))])
    if kind == 1:
        for _ in range(rng.randint(1, 8)): d[rng.randrange(len(d))] ^= 1 << rng.randrange(8)
```

### Task 12: CLI

**Arquivos:**
- Criar: `src/siftool/cli.py`, `src/siftool/__main__.py`
- Testes: `tests/test_cli.py`

**Interfaces:**
- Consome: API pública (Task 9), `supported_extensions()` (Task 3).
- Produz, em `siftool.cli`:
  - `main(argv: list[str] | None = None) -> int`
  - `output_path_for(src: Path, out_dir: Path | None, overwrite: bool) -> Path`: `<stem>_clean<suffix>`; se existir e sem `overwrite`, `<stem>_clean (2)<suffix>`, `(3)`…
  - `iter_inputs(paths: list[str]) -> list[Path]`: pastas são percorridas recursivamente, só com as extensões de `supported_extensions()`, pulando stems que terminam em `_clean` ou casam `_clean \(\d+\)$`. Arquivos passados explicitamente entram como vieram. A lista é ordenada.
- `__main__.py`: `raise SystemExit(main())`.

Formato da saída de texto:

| Comando | Linhas |
|---|---|
| `clean` | `f"{src} -> {dst}  [{status}]"`, depois `f"  removed: {label} ({category})"` (+ `f" - {detail}"` se houver), `f"  kept: {label} ({category})"`, `f"  note: {n}"`. Falha: `f"{src}  [failed] {error}"`. Por fim: `f"{total} file(s): {v} verified, {w} with warnings, {f} failed"`. |
| `scan` | `f"{path} ({format})"`, depois `f"  {category}: {label}"` (+ detail), ou `"  no metadata found"`. Erro: `f"{path}  [error] {msg}"`. |
| `verify` | `f"{path}  [{status}]"`, depois `f"  violation: {label} ({category})"` e `f"  note: {n}"`. |

JSON (`--json`):
- **clean:** o schema da spec seção 10. Cada achado é `{"category", "label", "detail", "where"}`. Falha: `"status": "failed"`, `"output": null`, `"error"`, com `removed`/`kept` vazios.
- **scan:** `{"schema": 2, "results": [{"file", "format", "findings", "notes"} | {"file", "error"}]}`.
- **verify:** `{"schema": 2, "mode", "results": [{"file", "status", "violations", "notes", "essential_match"}], "summary"}`.

Outros comportamentos:
- **Código de saída:** o pior do lote (`0`/`1`/`2`). `scan` sai com `2` se algum arquivo deu erro.
- **Encoding:** `sys.stdout`/`sys.stderr` com `reconfigure(encoding="utf-8", errors="replace")` no início do `main`.
- **`--out`:** criado com `mkdir(parents=True, exist_ok=True)`. Se falhar, a mensagem vai para o stderr e sai com `2`, sem traceback.
- **Erros por arquivo:** `SiftoolError` → a mensagem; `OSError` → `"File not found"` para `FileNotFoundError`, senão `str(e)`.
